# План натяжки верстки `fullready` на шаблон Битрикс «Интернет-магазин»

## 1) Подготовка и фиксация исходного состояния

- [ ] Создать отдельную ветку (например, `feature/fullready-integration`).
- [ ] Зафиксировать текущую версию проекта и сделать бэкап БД/файлов.
- [ ] Поднять проект локально в Docker и убедиться, что текущий шаблон работает без ошибок.
- [ ] Включить удобный режим разработки: отображение ошибок PHP, логирование JS-ошибок.

## 2) Аудит верстки из `fullready`

- [ ] Склонировать репозиторий `https://github.com/Halavyryn/fullready/tree/main` в отдельную директорию для анализа.
- [ ] Определить структуру страниц: главная, каталог, карточка товара, корзина, оформление заказа, личный кабинет, инфостраницы.
- [ ] Выделить все статические ресурсы: CSS, JS, шрифты, изображения, SVG-спрайты.
- [ ] Составить карту UI-блоков: шапка, меню, баннеры, карточки товаров, фильтр, футер, попапы.
- [ ] Проверить зависимости фронта (jQuery, слайдеры, маски, модалки, сборщики).

## 3) Проектирование соответствий с Битрикс

- [ ] Создать таблицу соответствий: каждый UI-блок `fullready` -> компонент/область Битрикс.
- [ ] Определить, какие части делаются через:
  - [ ] шаблон сайта (`header.php`, `footer.php`, `styles.css`, `script.js`),
  - [ ] шаблоны компонентов в `local/templates/.../components/`,
  - [ ] включаемые области `include/`.
- [ ] Зафиксировать, какие страницы остаются на стандартных компонентах и где нужны кастомные шаблоны.

## 4) Создание рабочей копии шаблона

- [ ] Не изменять базовый стандартный шаблон напрямую.
- [ ] Создать новый шаблон сайта (например, `fullready_shop`) в `local/templates/fullready_shop/`.
- [ ] Перенести в новый шаблон минимальный каркас: `header.php`, `footer.php`, `styles.css`, `template_styles.css`, `script.js`, `description.php`.
- [ ] Подключить шаблон в настройках сайта и проверить базовую отрисовку.

## 5) Перенос статики

- [ ] Скопировать CSS/JS/шрифты/изображения из `fullready` в папку нового шаблона (например, `assets/`).
- [ ] Привести пути к ресурсам к структуре Битрикс.
- [ ] Подключить стили/скрипты через `Asset::getInstance()` в `header.php`/`footer.php`.
- [ ] Проверить корректность загрузки ресурсов в DevTools (без 404 и дублей).

## 6) Натяжка каркаса сайта (layout shell)

- [ ] Разбить HTML `fullready` на:
  - [ ] глобальную шапку,
  - [ ] контейнер контента,
  - [ ] футер,
  - [ ] модальные окна/служебные блоки.
- [ ] Вставить динамические точки Битрикс: `ShowHead()`, `ShowPanel()`, `ShowTitle()`, `IncludeComponent(...)`.
- [ ] Подключить меню и служебные ссылки через стандартные компоненты Битрикс.

## 7) Главная страница

- [ ] Сопоставить секции главной (баннеры, хиты, новинки, бренды, блог) с компонентами Битрикс.
- [ ] Для каждой секции создать/настроить шаблон компонента под верстку `fullready`.
- [ ] Вынести повторяемые части в include-файлы или `result_modifier.php` шаблонов компонентов.

## 8) Каталог и карточка товара

- [ ] Настроить шаблон `catalog`/`catalog.section` под структуру карточек и сетку из `fullready`.
- [ ] Натянуть фильтр (`catalog.smart.filter`) и сортировку на UI из верстки.
- [ ] Адаптировать `catalog.element`: галерея, цена, SKU, кнопки покупки, табы, характеристики.
- [ ] Проверить совместимость с торговыми предложениями, остатками, ценовыми типами.

## 9) Корзина, оформление заказа, личный кабинет

- [ ] Натянуть шаблон корзины (`sale.basket.basket`) и мини-корзины в шапке.
- [ ] Адаптировать checkout (`sale.order.ajax`) под шаги/блоки дизайна.
- [ ] Привести страницы авторизации/регистрации/профиля к единому UI.
- [ ] Проверить сообщения об ошибках/валидацию и состояния пустых списков.

## 10) Контентные страницы и вспомогательные разделы

- [ ] Привести к общему виду: `about`, `contacts`, `delivery`, `guaranty`, `howto`, `news`, `search`, `store`.
- [ ] Унифицировать хлебные крошки, заголовки, боковые панели и типографику.

## 11) JS-логика и интерактив

- [ ] Подключить инициализацию плагинов после AJAX-перерисовок компонентов.
- [ ] Убедиться, что не ломаются стандартные скрипты Битрикс (корзина, избранное, compare и т.д.).
- [ ] Добавить делегирование событий для динамически подгружаемых элементов.

## 12) SEO и техническая корректность

- [ ] Проверить `urlrewrite.php`, ЧПУ, canonical, мета-теги, OpenGraph.
- [ ] Проверить микроразметку (товар, хлебные крошки, организация), если требуется.
- [ ] Проконтролировать редиректы и страницу `404.php` в новом стиле.

## 13) Тестирование

- [ ] Проверить адаптив на основных брейкпоинтах (mobile/tablet/desktop).
- [ ] Прогнать кроссбраузерную проверку (Chrome/Firefox/Safari/Edge).
- [ ] Проверить ключевые пользовательские сценарии:
  - [ ] просмотр каталога,
  - [ ] добавление в корзину,
  - [ ] оформление заказа,
  - [ ] авторизация/регистрация,
  - [ ] поиск и фильтрация.
- [ ] Проверить производительность (Lighthouse/WebPageTest), критические CSS/JS-блокировки.

## 14) Релиз

- [ ] Подготовить чек-лист выката: миграции, настройки, кеши, права на файлы.
- [ ] Сделать предпрод-ревью с заказчиком/дизайнером по pixel-perfect и UX.
- [ ] Включить композит/кеширование (по необходимости), прогреть кеш.
- [ ] Выполнить релиз и пост-релизный мониторинг ошибок.

---

## Рекомендуемый порядок выполнения (коротко)

1. Поднять новый шаблон `fullready_shop`.
2. Перенести статику и натянуть `header/footer`.
3. Сделать главную.
4. Сделать каталог + карточку товара.
5. Сделать корзину/checkout/личный кабинет.
6. Довести контентные страницы и SEO.
7. Провести тестирование и релиз.
